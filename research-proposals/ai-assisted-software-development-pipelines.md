# Fellowship Research Proposal

## Title

Evaluating Security Risks in AI-Assisted Software Development Pipelines: Measuring the Trade-off Between Developer Productivity and Security Outcomes

## Workstreams

Primary:
AI Security & Frontier Red Team

Secondary:
Economics & Policy

---

## Executive Summary

Frontier AI systems are increasingly being integrated into software development workflows. Developers now use AI systems to generate code, write tests, create infrastructure configurations, recommend dependencies, troubleshoot production issues, and automate engineering tasks.

While existing research has primarily focused on measuring productivity improvements, relatively little work has examined the security implications of AI-assisted development at scale.

This project seeks to evaluate whether the productivity benefits created by AI coding assistants are accompanied by measurable increases in security risk, technical debt, governance challenges, or operational vulnerabilities.

The research aims to provide empirical evidence that can inform AI deployment strategies, organisational governance frameworks, and future policy discussions surrounding AI-assisted software engineering.

---

# Background

Software development is rapidly becoming one of the most significant real-world deployment environments for frontier AI systems.

Developers increasingly rely on AI tools for:

• Code generation

• Infrastructure-as-Code creation

• Dependency recommendations

• Security remediation

• Documentation generation

• Incident response support

While these tools can dramatically increase productivity, organisations currently have limited evidence regarding their long-term security impact.

A critical unanswered question remains:

Does AI-assisted development create hidden security risks that offset productivity gains?

The answer has implications for:

• Enterprise security

• Workforce development

• Software quality

• Organisational resilience

• AI governance

• Technology policy

---

# Research Question

To what extent do frontier AI systems improve software development productivity while simultaneously introducing security vulnerabilities, governance risks, and technical debt into software development pipelines?

---

# Sub-Questions

1. Do AI-assisted developers produce code more quickly than non-assisted developers?

2. Do AI-assisted workflows introduce a higher rate of security vulnerabilities?

3. Which categories of vulnerabilities are most commonly introduced by AI-generated code?

4. How effective are current security controls at detecting AI-generated weaknesses?

5. Does heavy reliance on AI reduce engineers' ability to identify security flaws independently?

6. What governance mechanisms should organisations implement before deploying AI-assisted development workflows at scale?

---

# Hypothesis

AI systems significantly improve short-term software development productivity but may introduce hidden security risks that become apparent only after deployment.

Without appropriate safeguards, organisations may unknowingly exchange immediate productivity gains for increased security debt and reduced long-term resilience.

# Methodology

## Phase 1 – Experimental Environment

Create a benchmark suite of realistic engineering tasks.

Tasks include:

• Python application development

• Terraform infrastructure deployment

• Kubernetes configuration

• CI/CD pipeline creation

• Security remediation

• Dependency management

---

## Phase 2 – Human vs AI-Assisted Comparison

Participants divided into groups:

### Group A

No AI assistance

### Group B

Limited AI assistance

### Group C

Extensive AI assistance

Metrics measured:

• Completion speed

• Error rates

• Security vulnerabilities

• Quality of outputs

• Independent reasoning ability

• Vulnerability detection rates

---

## Phase 3 – Security Evaluation

Evaluate generated outputs using:

• Static analysis tools

• Security scanners

• Infrastructure scanning tools

• Expert review

• Vulnerability classification frameworks

Examples:

• Hardcoded secrets

• Excessive permissions

• Insecure defaults

• Dependency vulnerabilities

• Configuration weaknesses

---

## Phase 4 – Governance Analysis

Assess:

• Human oversight requirements

• Review processes

• Accountability structures

• Risk ownership

• Organisational controls
